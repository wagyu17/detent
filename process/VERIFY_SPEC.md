# 単語データ検証仕様 v1（第2段階、2026-10-19）

生成仕様（GEN_SPEC.md）で作った各語を、生成者とは別の担当が1語ずつ確認し、必要なら直す。結果は公開データの照合記録として残す。

## 確認すること（全語）
1. **訳の正しさ**：glossShort と glosses が、見出し語の主要な意味として正しいか（入力の definition・jHint と矛盾しないか）。品詞の形（名詞は名詞形、動詞は「〜する」、形容詞は「〜な／〜い」、副詞は「〜に」など）と pos が合っているか。
2. **4択での使いやすさ**：glossShort が10字以内で、正答を一意に指せるか。意味がほぼ同じ別の語と同じ訳になっていないか（同じ束の中で確認）。紛らわしい組は、意味の違いが分かる訳に直す。
3. **例文**：6〜12語、自然な英語で、見出し語を正しい意味・語法で1回使っているか。他の語がやさしいか。実在の人物・企業・商品・ブランド・試験名がないか。飲酒・喫煙・薬物・医療行為・病気・暴力・性・政治・宗教・ギャンブルの話題がないか。
4. **和訳**：英文に忠実で自然か。見出し語の訳が glossShort の意味と対応しているか。
5. **著作権**：有名な例文や教科書の文の再現でないか（疑わしければ作り直す）。

6. **配慮が必要な語**：死・自殺・殺人・暴力・虐待・犯罪・戦争・テロ・病気・性・薬物に強く結びつき、正解したときに祝う演出がそぐわない語には、その語の JSON に `"sensitive": true` を足す（それ以外の語には付けない）。10月版ではこの印の付いた語をパックから外し、公開データの説明に記録する。

## 出力
- data/build/verified/<バッチ名>.jsonl：GEN_SPEC と同じ形式（全語、同じ順。直していない語もそのまま含める）。
- data/build/verified/<バッチ名>.changes.json：直した語の一覧 `[{"headword":..., "field":..., "before":..., "after":..., "reason":...}]`（直していなければ空配列）。
- 形式の検証（JSON として読める、件数と順番、glossShort 10字以内、pos、例文の語数）を python3 で行ってから終える。
