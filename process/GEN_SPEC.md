# 単語データ生成仕様 v1（Detent、2026-10-19）

この仕様は、TSL 1.2（TOEIC Service List）と NAWL 1.2（New Academic Word List）の各見出し語に、日本語話者向けの学習データ（品詞・訳・例文）を付けるためのもの。生成物は CC BY-SA 4.0 の改変物として公開する（元リスト: TSL by Browne, C. & Culligan, B.／NAWL by Browne, C., Culligan, B., & Phillips, J.、いずれも CC BY-SA 4.0）。この文書は生成ログの一部として公開データに含める。

## 入力（data/build/batches/*.json）

- `headword`：見出し語（必須）
- TSL：`rank`（TSL の頻度順位）、`definition`（公式のやさしい英語の定義。空の場合あり）
- NAWL：`definition`（公式のやさしい英語の定義）、`posHint`（公式の品詞）、`jHint`（公式ファイルの日本語訳。参考情報）

## 出力（1語1行の JSON Lines。data/build/gen/<バッチ名>.jsonl）

```json
{"headword":"vacation","pack":"TSL","rank":2,"pos":"noun","glossShort":"休暇","glosses":["休暇","休み"],"example":{"en":"We are going on vacation next week.","ja":"私たちは来週、休暇に出かけます。"},"note":"","academic":null}
```

| フィールド | 規則 |
|---|---|
| `headword` | 入力のまま（大文字小文字・アクセント記号も変えない） |
| `pack` | `"TSL"` か `"NAWL"` |
| `rank` | TSL は入力の rank。NAWL は `null` |
| `pos` | 主要な意味の品詞。`noun` `verb` `adj` `adv` `prep` `conj` `pron` `det` `interj` `phrase` のどれか。NAWL は posHint（n→noun、verb→verb、adj→adj、adv→adv、n pl.→noun）に従う |
| `glossShort` | 4択の選択肢に使う最も代表的な日本語訳。**全角10字以内**。名詞は名詞形、動詞は「〜する」「〜を…する」の形、形容詞は「〜な」「〜い」、副詞は「〜に」「〜して」など、品詞が分かる形にする。括弧や記号はなるべく使わない。同じ束の他の語と同じ訳にならないよう、意味の違いが分かる語を選ぶ |
| `glosses` | 1〜2個。1個目は glossShort と同じか、より詳しい形。2個目は主要な別の意味がある場合だけ（なければ1個） |
| `example.en` | **オリジナルの英文**。6〜12語。見出し語をそのまま、または活用形で1回だけ使う。他の語はやさしい基本語（中学〜高校基礎レベル）。TSL はビジネス・職場・旅行・日常の場面、NAWL は大学・研究・論文の場面 |
| `example.ja` | 英文の自然な日本語訳。見出し語の訳が glossShort の意味と対応していること |
| `note` | 任意。紛らわしい点や代表的な語法を全角30字以内で。なければ空文字 |
| `academic` | NAWL だけ：学術英語での出会いやすさを 1〜5 の整数で（5＝論文で非常によく見る、1＝まれ）。TSL は `null` |

## 守ること

1. **市販の単語帳・辞書の訳や例文を写さない**（著作権）。訳は一般的な語義を自分の言葉で書き、例文は自分で作る。有名な例文や教科書の文を再現しない。
2. 例文に**実在の人物名・企業名・商品名・ブランド名、試験名（TOEIC・TOEFL など）を入れない**。人名が必要なら一般的な名前（例：Ken、Emma）にする。
3. 例文で**飲酒・喫煙・薬物・医療行為・病気・暴力・性・政治・宗教・ギャンブル**の話題を扱わない（年齢区分を4+に保つため）。語そのものがこれらの分野の語でも、中立的な文脈（研究・統計・制度など）で作る。
4. 誤った意味・不自然な英語を避ける。迷う語は最も一般的な意味を選ぶ。
5. `jHint` や `definition` は参考にしてよいが、訳はそのまま書き写さず、学習者に分かりやすい形に整える。
6. 出力は**有効な JSON Lines**（1行1語、余分な文字なし、UTF-8）。入力のすべての語を、入力と同じ順で出力する。

## 検証（第2段階）の観点

- 訳が主要な意味として正しいか。glossShort が10字以内で、4択で正答を一意に指せるか。品詞の形と合っているか。
- 例文が自然で、見出し語を正しい意味・語法で使っているか。語数、禁止の話題・固有名詞がないか。
- 和訳が英文に忠実で自然か。
- 問題があれば修正し、修正内容を記録する。
